# CCTV App 方案评估

## 现状

你之前的版本已经验证了一个核心思路：直接把 CCTV 官方直播页封进 Android `WebView`，配合遥控器按键切台，能在投影仪上快速形成一个“电视机式”的使用体验。

但原实现有几个明显痛点：

1. 频道数据写死在 Java 里，后续补频道、改名称、换封面都要重新发版。
2. 切换上一频道时使用了取模运算的负数写法，存在下切越界的隐患。
3. 页面如果没识别到全屏按钮，会一直停留在加载态，实际可观看但 UI 不会放行。
4. 超时任务没有区分“当前页面”和“上一个页面”，切台快时会互相干扰。

## 更好的方案

我建议保留 `WebView` 方案，不去抓取或转封装 CCTV 的真实流地址，而是做成“频道目录驱动”的官方页面壳。

### 为什么这样更稳

1. 官方直播页本身就是可播放入口，不需要额外解析 m3u8。
2. 频道地址相对稳定，维护成本低。
3. 把频道列表外置后，后续扩展只需要改配置文件，不需要再动播放器逻辑。
4. 仍然适合投影仪、电视盒子这类“少操作”的场景。

## 实现策略

### 1. 频道目录外置

频道列表放在：

`app/src/main/assets/cctv/channels.json`

这样图片、名称、地址都能统一管理。

### 2. 播放器逻辑保持轻量

保留单个 `WebView`，只负责：

1. 打开频道页
2. 监听加载状态
3. 在页面可用后尽量自动播放和全屏

### 3. UI 放宽失败条件

如果页面没有找到全屏按钮，也先把网页展示出来，避免“明明能看但 UI 卡住”的情况。

### 4. 切台时防串扰

用加载序号区分本次切台和上次切台，避免旧超时任务误伤新频道。

## 当前实现结果

这次已经落地的内容：

1. 频道目录改成了外置 JSON。
2. 主界面改成左侧频道列表、右侧播放区。
3. 支持遥控器上下左右直接选台。
4. 补齐了 CCTV-4 欧洲、CCTV-4 美洲等频道。
5. 修复了下切频道时的负数取模问题。
6. 加强了加载态和失败态的文案。
7. 放宽了“必须识别到全屏按钮才算可用”的限制。

## 后续可继续做的增强

1. 加一个“频道收藏”。
2. 加一个“最近观看”。
3. 加一个本地搜索框，方便遥控器不友好的场景。
4. 如果你后面想做成更像真正 App 的版本，可以把 `WebView` 换成 ExoPlayer + 真实流地址，但那会增加维护成本。
